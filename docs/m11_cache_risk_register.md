# M11 Shared Context Cache Risk Register

This register supports P-M4-A design review only. No runtime cache is
implemented by this document.

| Risk | Failure Mode | Impact | Mitigation | Test Required Before Implementation |
|---|---|---|---|---|
| stale report cache | A report JSON changes after a cache key is created, but the cached summary/evidence table remains served. | Dashboard and AI Context Manifest can show outdated status, source, or freshness information. | Include required report file mtimes and sizes in the cache key; invalidate on any signature change. | Modify a report fixture between calls and assert cache invalidation plus identical uncached output after rebuild. |
| stale market_history DB cache | The local market history SQLite file changes while cached D13/D14-derived rows remain active. | Historical normalization, liquidity, and downstream model context can be stale. | Include DB mtime and size in the cache key; support explicit refresh-run completion invalidation later. | Touch or replace a temp DB and assert `cache_invalidated_by_market_history_change`. |
| write_last_good side-effect suppression | A future cache path skips `build_dashboard_evidence_table(write_last_good=True)` side effects. | Last-good evidence semantics drift; stale fallback behavior becomes misleading. | Bypass cache for `write_last_good=True`; never treat cached rows as a completed write path. | Spy on last-good write calls and assert the write path is preserved; assert `cache_bypassed_for_write_last_good`. |
| filtered evidence table cached incorrectly | A filtered table is stored as if it were the unfiltered evidence table. | Later callers see missing modules/rows and AI Context Manifest counts drift. | Cache only unfiltered evidence tables; apply filters after reading unfiltered cached rows. | Request filtered then unfiltered evidence table and assert unfiltered row count/modules remain intact. |
| cached response object mutation | A caller mutates a cached response object in place. | Later responses inherit accidental mutations or missing fields. | Store immutable data or return defensive copies from cache. | Mutate first response in a test and assert a second cache read is unchanged. |
| AI Context Manifest inclusion/exclusion drift | Manifest reuse bypasses existing exclusion rules or uses stale evidence rows. | Missing/research_needed/stale rows could enter included context, or model-output counts could change. | Build manifest only from current cached evidence rows and reuse existing manifest builder logic. | Compare cached and uncached manifest included/excluded fact/model-output counts and excluded reasons. |
| portfolio privacy expansion | Cache key, diagnostics, or cached payloads accidentally include holdings, account values, or private portfolio details. | Private data could appear in memory diagnostics, logs, or AI context. | Cache only sanitized dashboard/context response objects; exclude private account fields and raw compact inputs from key/debug data. | Scan cache diagnostics and response bodies for holdings/account/privacy sentinel strings. |
| accidental external AI/productization coupling | Cache is wired into preview or manifest work in a way that also opens productized model/search behavior. | Frozen external boundary could be reopened accidentally. | Keep cache local-only and service-internal; do not add providers, endpoints, search calls, or prompt persistence. | Route audit shows no new external/search routes and preview flags remain local-only. |
| concurrent request race | Two FastAPI requests refresh the same cache key concurrently and partially update shared state. | One request could see partial data or mismatched summary/evidence pairs. | Use a small lock around refresh/replace; publish complete snapshots atomically. | Concurrent requests assert no exceptions and all returned snapshots have matching generated_at/module counts. |
| cache key path confusion for custom reports_dir | Custom report paths reuse the default cache key or collide after relative-path differences. | Tests or local tools can see data from the wrong reports directory. | Resolve paths in the key; bypass or use separate keys for custom `reports_dir` and `market_history_db_path`. | Build two temp report dirs with different values and assert no cross-contamination. |
| generated_at instability in tests | Cached vs uncached paths differ only because generation timestamps are dynamic. | Tests become flaky or assert accidental timestamp behavior instead of contracts. | Assert semantic counts/keys first; control generated_at in fixtures; document timestamp behavior. | Fixture-based cached/uncached comparison with fixed generated_at values. |
| cache hiding degraded audit state | Cache keeps a previously healthy audit snapshot after current data becomes degraded. | Operators miss degraded state or stale provider/report signals. | Include all audit-relevant report and DB signatures; expose stale markers in diagnostics. | Change fixture status from ok to degraded and assert cache invalidation plus degraded status visibility. |
